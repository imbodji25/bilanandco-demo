Le squelette reprend la forme de ce qui va s’afficher

Les os sont en gris très clair, et une lueur les traverse en 1,6 seconde. Le squelette garde le nombre de colonnes et la hauteur de ligne du tableau réel, pour que rien ne saute quand les données arrivent. Un écran qui répond en moins de 200 millisecondes n’en affiche pas.

Un code, une cause, une action

Le code sert au support et à la recherche dans la documentation ; il est toujours visible, jamais masqué derrière un « voir le détail ». Le filet est rouge quand l’action est impossible, ambre quand elle reste possible mais risquée. Le message nomme le montant, la date ou la pièce en cause, et le bouton mène à l’endroit où corriger.

Règles d’emploi

Six règles qui valent pour les trois familles

Un seul état à la foisUn écran montre le squelette, puis les données, puis le vide ou l’erreur. Jamais un squelette au-dessus d’un message d’erreur.
Le vide n’est pas une erreurPas de rouge, pas d’ambre, pas de point d’exclamation : un dossier neuf est un état normal du produit.
Le bouton dit le geste« Importer un FEC », pas « Commencer ». Le libellé reprend le verbe de l’action qui sera réellement déclenchée.
Le code d’erreur est stableTrois lettres de famille, trois de domaine, trois chiffres. Il ne change pas quand le message est réécrit.
Le squelette ne ment pas sur la formeMême nombre de colonnes et même hauteur de ligne que le tableau réel, sinon la page saute au chargement.
Tout état est annoncéLe squelette porte aria-busy, l’erreur porte role="alert" : une personne qui écoute l’écran est prévenue comme les autres.

Planche de référence. Ces trois familles remplacent toute variante inventée écran par écran : un état absent de cette page doit y être ajouté avant d’être utilisé ailleurs.
